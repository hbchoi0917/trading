# 옵션 스크리너 — 데모

[English](README.md) | **한국어**

관심 종목을 매일 스캔해 풋 크레딧 스프레드 진입 후보를 찾는, 바로 실행해볼 수 있는 스크리너입니다.

> **데모/학습용 베이스라인입니다.** 실거래에 쓰려면 커스터마이징이 필요하고,
> 주문 실행·포지션 모니터링·클라우드 배포까지 완전 자동화하려면 브로커 API 연동이
> 추가로 필요합니다. 자세한 내용은 [`screener.py`](screener.py) 상단 주석을 참고해 주세요.

---

## 필터

아래 조건을 모두 통과해야 시그널이 생성됩니다.

| 필터 | 지표 |
|------|------|
| 추세 | 주가 > 200일 이동평균(SMA-200) |
| 모멘텀 | RSI(14) — VIX 레짐에 따라 기준값 조정 |
| 평균회귀 | 볼린저 밴드 위치 (하단 밴드 근접도) |
| 변동성 | ATR% 최소값 이상, 거래량 > 50일 평균 |
| 프리미엄 품질 | IV Rank ≥ 25, IV/HV ≥ 1.0 |
| 어닝 | 발표일 전후 설정 구간에는 스킵 |
| FOMC | 금리 결정일에는 경고 |

**VIX 레짐 조정** — RSI와 볼린저 밴드 기준값이 4개 레짐(LOW / NORMAL / ELEVATED / HIGH)에 따라 바뀌어, 시장 상황이 달라져도 진입 기준이 맞게 유지됩니다.

## 방법론 노트

### 시그널

- **일봉이 아닌 시간봉 RSI** — 큰 하락일에 일봉 RSI는 중립(~50)으로 나오는데 시간봉 RSI는 과매도를 제대로 보여줍니다. 일봉은 전일 종가를, 시간봉은 지금 시장을 반영하기 때문에 장중 진입 판단에는 시간봉을 씁니다. 장중 데이터가 없으면 일봉으로 폴백합니다.
- **실시간 장중 패치** — 스크리닝 전에 당일 OHLCV 바를 장중 실시간 데이터로 갱신해, 전일 종가가 아닌 현재가 기준으로 시그널을 냅니다.
- **지수는 종목과 다르게 스크리닝** — 유럽식·현금결제 옵션인 지수는 조기 배정 리스크가 없어 RSI를 진입 조건으로 쓰지 않습니다. RSI는 방향성 트레이더의 도구이고, 프리미엄 매도자에게 엣지가 있는지 알려주는 건 IV Rank입니다. 지수 진입은 장기 이동평균으로 추세만 확인하고 IV 이중 필터를 통과하면 됩니다.
- **IV 이중 필터** — 1차로 현재 IV가 자기 52주 이력 대비 높은지(IV Rank), 2차로 시장이 최근 실현변동성보다 비싸게 옵션을 사고 있는지(IV/HV)를 봅니다. 둘 다 통과해야 합니다. IV 데이터를 못 받으면 fail-open으로 처리해 데이터 장애 때문에 정상 진입이 막히지 않게 하되, IV 데이터가 계속 안 들어오는 상품은 품질 게이트 없이 거래되도록 두지 않고 일시 중지합니다.
- **확신 수준별로 다른 스크리닝 조건** — 실적이 검증된 소수 종목은 "상승 추세 속 과매도 눌림"이라는 방향성 타이밍 패턴 대신, 변동성과 프리미엄 품질만 보는 간소화된 진입 조건을 씁니다. 방향 선별력을 일부 내주고 진입 빈도를 얻는 트레이드오프로, 실제 결과로 검증된 종목에만 적용하고 신규 종목은 풀 패턴부터 통과해야 합니다.

### 종목 선정 & 기준값 보정

- **거래당 실현손익 기준 종목 선정** — 거래 종목은 여러 분기의 실제 거래 이력으로 주기적으로 재평가하되, 거래 빈도나 총손익이 아니라 **거래당 실현손익**으로 순위를 매깁니다. 빈도·총액 기준은 거래가 잦고 마진이 얇은 종목을 과대평가하기 쉽기 때문입니다. 구조적으로 부진한 종목은 다른 조건이 완화돼도 계속 제외하고, 한 달 부진과 지속적인 패턴은 구분해서 판단한 뒤 제외나 신규 편입을 결정합니다.
- **기준값은 짐작이 아니라 near-miss 데이터로 보정** — 스크리닝 기준과 최소 크레딧은 여러 세션에 걸친 탈락 로그를 보고 다시 검토합니다. 탈락한 후보가 기준 바로 아래에 몰려 있을 때만 기준을 완화하고, 기준보다 한참 아래에 흩어져 있으면(예: 거래량 필터가 실제로 확신 낮은 움직임을 걸러내는 경우) 필터가 의도대로 동작하는 것으로 보고 그대로 둡니다.

### 성과 측정

- **원장 기준 포지션 식별** — 브로커는 행사가별 순수량만 보여주기 때문에, 우연히 행사가를 공유하는 포지션들을 구분할 수 없습니다. 실제로 무엇을 진입했는지는 브로커가 아니라 시스템 자체 원장(ledger)을 기준으로 삼고, 브로커에서는 실시간 가격과 원장에 없는 정보만 가져옵니다.
- **현금흐름이 아닌 실현손익으로 성과 측정** — 요약 알림은 이번 달 실현손익을 전월, 분기 누적과 함께 보여줍니다. 기간 내 받은·지급한 프리미엄을 모두 더한 순현금흐름은 일부러 쓰지 않습니다. 크레딧 스프레드는 결과가 나오기 전에 현금이 먼저 들어오기 때문에, 신규 포지션이 많은 달은 미해결 손실을 안고도 수익처럼 보일 수 있습니다. 실제 거래 이력에서도 월별 현금흐름과 실현손익이 크게 벌어졌고, 한 달은 방향이 아예 반대였습니다.
- **거래당이 아니라 자본 보유 일수당 수익률로 비교** — 청산은 사유별(목표 수익 / 시간 기준 청산 / 손절)로 묶어, 리스크 1달러·보유 1일당 실현수익률로 비교합니다. 그래야 빨리 끝난 작은 수익과 오래 걸린 큰 수익을 단순 금액이 아니라 제대로 견줄 수 있습니다.

## 사용법

```bash
python screener.py
```

`signals_YYYYMMDD.csv`와 콘솔 테이블이 출력됩니다. 각 행은 모든 필터를 통과한 종목이고, RSI, 볼린저 밴드 위치, IV Rank, IV/HV, 추천 만기일이 함께 나옵니다.

## 커스터마이징

| 파라미터 | 위치 | 참고 |
|----------|------|------|
| 관심 종목 | `WATCHLIST` | 예시 종목을 직접 분석한 종목으로 교체 |
| RSI / 볼린저 기준값 | `VIX_REGIMES` | 바꾸기 전에 본인 거래 이력으로 백테스트 |
| 목표 델타 | `DELTA_TARGET` | 낮을수록 더 OTM → 승률은 높고 프리미엄은 낮음 |
| DTE 구간 | `DTE_MIN / DTE_MAX` | 월물 스프레드는 보통 21–45일 |
| IV Rank 하한 | `IV_RANK_MIN` | 올릴수록 프리미엄 품질을 더 까다롭게 봄 |

## 완전 자동화하려면

실운영 시스템으로 돌리려면 다음이 필요합니다.

1. **브로커 API** — Tastytrade, IBKR 등으로 주문 실행 추가
2. **클라우드 서버** — AWS EC2(Ubuntu)에 배포하고 미국 동부시간 기준 cron으로 스케줄링
3. **알림** — 진입·청산 이벤트에 Telegram 또는 이메일 알림
4. **포지션 모니터** — 목표 수익이나 DTE 기준에 도달하면 자동 청산하는 로직
5. **포지션 원장 + 대사** — 모든 체결을 영속적인 원장에 기록하고, 매 실행마다 브로커의 실제 포지션과 대사해 손익이나 리스크 한도가 틀어지기 전에 불일치를 알림
6. **실거래 안전장치** — 드라이런·페이퍼 플래그를 기본값 ON으로 두고, 실계좌 첫 단계는 최소 사이즈(저위험 단일 종목, 1계약, 동시 보유 포지션 상한)로 시작

서버 셋업 스크립트와 cron 템플릿은 [`deploy/`](../deploy/)에 있습니다.
주문 실행, 모니터링, 대사, 실거래 안전 게이트까지 갖춘 실운영 시스템은 private 레포에서 운영하며, 이 레포는 스크리닝 베이스라인입니다.
